# v3.49.0 — turnkey coverage, across the board

*2026-07-07 · the review's setup-friction finding, generalized and closed ·
design + field story: `research/26-turnkey-coverage.md` · details:
`CHANGELOG.md`*

## Not a Rust problem

The LLM field review (docs/LLM_REVIEW.md) hit a ~150-line wiring gap between
`scaffold_coverage`'s Rust template and a usable per-test coverage matrix.
The audit showed it was never just Rust: of the five languages the scaffold
covers, only Python was turnkey — Go, JS/TS, Rust, and Java all shipped a
TODO stub. The behavioural toolkit (the moat) was reachable unaided in
exactly one language.

## The design insight

The hard part of every converter is mapping covered lines to functions with
ids that match stitchgraph's node ids. But the kit is *generated by
stitchgraph* — whose index already holds every function's span. So each kit
now ships **`spans.json`** (per-file `[node id, start, end]` tables), and one
stdlib-only converter handles all three new formats (llvm-cov export JSON,
Go coverprofiles, istanbul JSON) as the same trivial lookup:

    covered line → innermost enclosing span → node-id-exact function id

No language parser, no stitchgraph, no network inside the sandbox.

## What's turnkey now

| language | capture | granularity |
|---|---|---|
| Python | coverage.py `--cov-context=test` (unchanged) | per test |
| **Rust** | cargo-llvm-cov: one instrumented build, then per test: wipe profraws → `--exact` → JSON export (~0.5 s/test measured) | per test |
| **Go** | `go test -run '^<Test>$' -coverprofile -coverpkg=./...` per test | per test |
| **JS/TS** | jest or vitest, istanbul JSON, one run per test file | per test **file** (honest note in the kit) |
| Java | still a template — JaCoCo per-test attribution needs build-system integration a generated script can't do responsibly | — |

## Field proof, on the reviewer's own scenario

The generated Rust kit ran against **fd** unedited: 267 tests captured, 316
functions attributed, and `find_modes` answered — intrinsic dimensionality 7,
16 behavioural modes, a minimal covering test set of 154, mode 0 the
CLI-options cluster. The task that cost the reviewer ~150 hand-written lines
is now `stitchgraph scaffold-coverage` + `bash run_coverage.sh`. Go and both
JS runners validated with exact attribution on fixture projects
(`TestMul → {Add, Mul}` because `Mul` calls `Add`).

## Compatibility

No schema change, no API change, no new Python dependency. Regenerate any
existing coverage kit to pick up the runnable scripts and `spans.json`.
